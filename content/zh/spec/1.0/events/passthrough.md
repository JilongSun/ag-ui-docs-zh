有两种事件（event）类型承载协议没有建模的东西：`RAW`，一个未经翻译直通的原生提供方事件；以及 `CUSTOM`，应用自己的事件。两者都是独立的——它们不开启也不关闭任何属于自己的项，且可以（MAY）出现在一次已打开运行（run）内的任何位置，不过 `CUSTOM` 与 `RAW` 不同，它确实会在自己的通道内结束一条已打开的[分片流](../basic/patterns/streaming.md#关闭分块流)。它们的限制正是关键所在：本页的一切，都是为了让这些逃生通道无法悄悄变成第二个协议。

## `RAW`

把原生提供方事件未经翻译地直通，供需要协议未建模细节的消费者（consumer）使用。

```json
{
  "type": "RAW",
  "event": { "…the provider's own event…": true },
  "source": "openai"
}
```

- `event` 是必需（REQUIRED）的，可以是任何 JSON 值；`source` 是可选（OPTIONAL）的，指明它来自哪个提供方或框架。
- 消费者不得（MUST NOT）从 `RAW` 事件推导协议行为：其中没有任何东西会开启、关闭或修改本规范跟踪的任何东西。
- 生产者（producer）应当（SHOULD）把 `RAW` 与标准事件一同发出，而绝不取而代之。一个*只*用 `RAW` 表达某事物的生产者，并没有把它放进协议。

同一份载荷也作为普通事件上的 `rawEvent` 字段传输——那种写法把来源附加到一个已翻译的事件上，而 `RAW` 承载的是没有已翻译事件与之对应的材料。

## `CUSTOM`

协议为应用自有事件提供的扩展点。

```json
{
  "type": "CUSTOM",
  "name": "com.example.cart-updated",
  "value": { "items": 3 }
}
```

- `name` 与 `value` 是必需（REQUIRED）的——没有名称，消费者无法路由该值；而没有载荷的事件什么也说明不了。
- 不认识某个 `name` 的消费者必须（MUST）忽略该事件。这是协议允许的流量，而不是[未识别材料](../basic/processing.md)：不剥离任何东西，也不产生任何告警。
- 名称属于应用空间。生产者应当（SHOULD）给自己发明的名称加上厂商或应用标识符前缀，这样两个扩展同一条流的参与方不会撞名；不带前缀的名称保留给协议自身将来使用。
- 消费者对已识别的 `CUSTOM` 事件所做的任何事都在协议之外。生产者不得（MUST NOT）依赖 `CUSTOM` 事件来承载本规范指派给标准事件的语义——一个符合规范（conformance）的消费者被允许忽略的自定义「消息（message）」，并不是一条消息。

## 安全考量

透传内容按定义就是没有经过校验的：没有任何 schema 约束 `event` 或 `value`，而 `RAW` 载荷来源于提供方取得它们的任何地方。消费者必须（MUST）把两者都当作不受信任的输入——绝不作为标记渲染、绝不执行、绝不授予权威——并且应当（SHOULD）以审视它所概括的网络流量时同样的怀疑态度，对待 `RAW` 载荷。
